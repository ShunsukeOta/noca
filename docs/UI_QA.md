## 1. テストの目的

Firebaseや外部通信を実装する**前**に、3画面の見た目とiPhoneでの操作感を合格させる。

最重要の4点:

1. iPhone Safariとホーム画面追加後のPWAで表示が崩れない
2. TODO / カレンダー / メモを迷わず操作できる
3. キーボード・シート・タブバー・Safe Areaが衝突しない
4. 日本語長文・小画面・ダークモードで読みやすさを保つ

## 8. 記録の形式

Phase 1E では、結果をPR本文または追加文書に次の形式で記録する。

~~~text
Test ID: C-06
Date: YYYY-MM-DD
Device: iPhone (モデル名)
iOS: xx.x
Mode: Safari / Home Screen PWA
Viewport: xxx × xxx CSS px
Theme: Light / Dark
Result: PASS / FAIL / BLOCKED
Evidence: スクリーンショットまたは画面収録へのパス
Issue: 発生条件、再現手順、期待結果、実際の結果
~~~

同じ問題を修正したら同条件で再テストし、PASSに更新する。スクリーンショットに個人名、メール、招待URL、トークンなどを含めない。

## 9. 合否・UI凍結の条件

Phase 1Eの **Go条件**:

- **Must** のケースがすべてPASS
- 重大なレイアウト崩れ、入力不能、タブ/シートの重なり、意図しないズームが0件
- Safariとstandaloneの両方で主要導線を最後まで操作できる
- TODO/カレンダー/メモの **通常画面・追加編集画面・空状態** のキャプチャがある
- ライト/ダーク双方でメイン画面を比較済み
- デザインシステムの最終値をドキュメントへ反映
- ユーザーのデザイン承認を得る

Phase 1では **Firebaseの接続、通知、複数端末同期を合格条件に含めない**。それらはPhase 2–4に分離する。
