# noca — UIデザインシステム

- Version: 0.3
- Updated: 2026-10-15
- Target: iPhone Safari / ホーム画面に追加したPWA
- Status: **共通UI基盤を実装済み。Phase 1Eの実機QAはメンテナーから完了報告あり**（個別記録なし）。Phase 2で追加したアカウント／招待画面は実機未確認。
- UI library: Tailwind CSS v4 + Radix Dialogを基礎にしたローカルUIコンポーネント
- Reference: 先に作成した「TODO / カレンダー / メモ」のデザインボードは**方向性の参考**。画像内の日本語・数値・画面部品はそのまま仕様と見なさない。

## 1. デザインの方向性

**静か・明快・軽い・親しみやすい。** Apple純正の簡潔な情報設計を参考にしつつ、ブランド独自の落ち着いたブルーを使用。必要な場所だけに柔らかなアクセント。グラスモーフィズムや過度な影で情報を隠さない。

### 守るべき5原則

1. TODO追加は即時、細かい入力は任意にする
2. 3タブは常に判別でき、下部に固定する
3. 一覧は読みやすく、余白・罫線・色で階層を整理する
4. 作成・編集は下部シートで自然に完結させる
5. 「2人で共有」は自然に伝え、毎回の共有操作は発生させない

### テキストのルール（2026-10-14 確定）

- TODO・カレンダー・メモの画面冒頭に可視のH1やページ名を置かない。現在の画面は下部グローバルメニューで示す
- 「今日も〜」「ふたりで〜」など気分を盛り上げるためだけの文章は表示しない
- 件数・日付・フィルター・ボタン・フォームラベル・バリデーション・空状態の説明など、操作に必要な文言は残す
- 空状態は短い状態名と必要な追加アクションだけで構成し、励まし文・説明文を付けない
- 作成・編集シートはタイトルと入力項目のみ表示し、意図のない説明文を入れない
- プレビュー状況・開発Phaseなどのテスト向けコピーを一般利用画面へ表示しない。ユーザーに影響する保存失敗等は例外

## 3. タイポグラフィ（暫定）

- Font stack: `-apple-system, BlinkMacSystemFont, "Hiragino Kaku Gothic ProN", "Hiragino Sans", "Noto Sans JP", sans-serif`
- 画面冒頭のH1: 使用しない（共通ナビゲーションで現在地を明示。mainにはアクセシブルなラベルを付ける）
- H2 / セクションタイトル: 20px / 600 / 1.4
- List title: 16px / 500–600 / 1.45
- Body: 16px / 400 / 1.5
- Secondary: 13–14px / 400–500 / 1.45
- Caption: 12px / 400 / 1.4（補助情報専用。主要操作には使わない）
- 編集用input / textarea: **16px以上**。iOS Safariの自動ズームを防ぎ、読みやすさを保つ。
- 表示幅や文字の拡大設定で切れないようにする。日本語2行以上のタイトルも許容。

## 4. レイアウト・サイズ

- 対象幅: 320–430 CSS pxを想定。重点レビュー: **375 / 390 / 430px**
- アプリコンテンツ: 1カラム。デスクトップ用ブレークポイントUIは不要
- PCプレビュー時は画面全体のスクロールバーを隠し、ホイール・トラックパッドでのスクロールは維持する。モーダルなど内部スクロール領域のバーは対象外
- 基本画面余白: 左右16px / セクション間16–24px
- 間隔ステップ: 4, 8, 12, 16, 24, 32px
- 角丸: 小8px / 中12px / シート・大カード16–20px / FAB full
- タップ領域: 原則44×44 CSS px以上
- 主要ボタン高さ: 44–48px
- 下部ナビ: 3タブ＋独立した追加CTA。角丸のフローティングDock（画面左右16px、下端12px＋safe-area-inset-bottom）、高さ68px前後
- 下部タブはキーボード表示に引きずられない設計にする。キーボード表示中の導線はUIテストで決定
- 上部ヘッダー（nocaロゴ・日付・共有アイコン・設定）は `position: sticky; top: 0` で常時表示。ノッチ等のsafe areaを含める
- スクロール中は半透明の背景と軽いbackdrop blur、控えめな下罫線で本文との境界を明確にする
- ヘッダーは通常の文書フローを保ち、ページ本文が背後から始まらないようにする。ドロワーはヘッダーより前面に置く
- TODO/カレンダー/メモ/設定の全画面、320/390/430pxでスクロール固定・横はみ出し・歯車ボタンの操作を検証する
- 下部シート: 上部ドラッグハンドル（採用時）、スクロール領域、閉じる導線、安全な保存/破棄ルール
- 空白領域を意図的に残す。各要素をカードで囲みすぎない

### Safe Area / Viewport

- `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">` を基本にする
- `padding-bottom: env(safe-area-inset-bottom)` などのsafe areaを使用
- `100dvh` / `100svh` などを用途に応じて使い分け、アドレスバー表示変動を検証
- `maximum-scale=1` や `user-scalable=no` を使って拡大操作を禁止しない
- iPhone Safari とstandaloneモードで見え方を両方確認する

## 5. ナビゲーション・共通要素

### 設定画面

- ヘッダー右側に歯車アイコン（44px以上のタップ領域）を配置する。設定画面では同じ位置のアイコンを「×」に切り替え、押すと開く前のタブへ戻す（直接URLで開いた場合はTODO）。旧ダークモードアイコンは削除し、テーマ切替は設定画面に一本化する。
- `/settings` はメイン3タブとは別の補助画面。下部のグローバルメニュー全体を隠し、コンテンツ下部にDock用の空白を残さない。設定への遷移はアニメーションを使わず即時表示し、ヘッダーの「×」で戻る。
- 画面上部に「戻る」と「設定」。戻り先は開く前のタブ（直接リンクで開いた場合はTODO）。
- ライト／ダークは実際の既存テーマ状態と連動し、端末の `localStorage` に保存する。
- Firebase環境設定がない場合はログイン・招待を「準備中」と表示する。設定済みならGoogleログイン・共有スペース・招待リンクを実際に操作できる。招待リンクにはコピーと、対応端末でのネイティブ共有シートを並べる。共有シート非対応時もコピーを使える。通知は未実装。TODO/予定の共有同期コードはあるが、Rulesのデプロイと実環境受け入れ確認が残る。
- データの保存先が現在「この端末内」であることを表示する。TODOと予定は保存され、メモは開発中で入力や保存ができないことを明確にする。
- 設定の「TODOカテゴリ」は1行の入力欄・削除アイコン・ドラッグハンドルで構成する。入力名はフォーカスが外れたときに、変更がある場合だけ保存する。左の色丸から8色の選択モーダルを開き、色は選択直後に反映する。カテゴリ削除時は、所属TODOがある場合だけ移動先を選択してから確定する。0件なら移動先を表示せず、そのまま削除できる。色は共通パレットから選び、カテゴリごとの任意HEX入力は設けない。
- 共通ヘッダーのnocaロゴの右側に「今日の日付（曜日付き）」を短いチップとして常時表示する。古い「ふたりのスペース」文言とロゴ下の重複日付は表示しない。
- メンバーを示すアバターはヘッダーだけでなくTODO行・カレンダーの担当欄と予定編集にも使う。FirebaseメンバーはGoogleプロフィール画像を表示し、画像がない・読み込めない場合は名前の先頭文字を使う。2人利用時はA/Bの枠を本人の表示名と画像に結びつける。初期状態は「自分」1人で、Bのアバターや担当ラベルを表示しない。
- PWA manifestのホーム画面ショートカットは「TODOを追加」と「今日の予定」の2つ。前者はTODO入力シートを開き、後者はカレンダーで端末の今日を選択する。ショートカットの表示はOS/ブラウザーの対応に従う。
- 320px幅でも日付チップ・共有アイコン・設定ボタンが横にはみ出さないようにする。日付は端末のローカル日付を使用し、日付変更時やPWA復帰時に更新する。

### iPhoneソフトウェアキーボード時のシート

- シートを開くだけではタイトル入力へ自動フォーカスしない（キーボードの勝手な出現を避ける）
- キーボードが開いた場合だけ `visualViewport` の可視領域の高さ・上端を計測し、シート底辺をキーボード上へ移動する
- シート最大高を可視領域に制限し、ヘッダーは縮小、内容は独立スクロール、保存ボタンは下部に固定する
- キーボードが閉じたら通常の丸いボトムシートへ復帰する
- 標準Safari / ホーム画面PWA の両方で、入力欄・保存ボタン・閉じるボタンの可視性を実機確認する
- この挙動は Visual Viewport が利用できない環境では従来のシートにフォールバックする

### Floating Bottom Dock

- 左の**TODO / カレンダー / メモの3タブだけ**を、角丸の白/暗色フローティングカードにまとめる。右端の＋は白いカードに含めない
- **カードと独立＋ボタンの間に16pxの空間**を取る（横並びで同じ高さに中央揃え）。区切り線は不要。画面左右16px、下端12px＋safe-area-inset-bottom
- 3タブはアイコン＋小さな日本語ラベル。アクティブ背景はスプリングで移動。メインメニューリンク数は3本のまま
- 右端の独立「＋」は**タブではなく実際の操作ボタン**。ブランドの濃い面色・60×60px・角丸21px・持ち上がった影・押下時の縮小で明確に差別化
- ＋を押したらTODOまたはカレンダーの追加シートを開き、追加先を再選択させない。メモタブでは＋を隠す
- `/settings` は同じDockの3タブを維持するが＋は表示しない
- Safe Areaの上にDockを浮かせ、長い一覧の末尾が下部Dockに隠れないよう十分な余白を取る。背景のドロワーはNavよりも前面に出す
- ヘッダー側: 設定ボタン。現在画面の状態はタブ切替で不意に失われないようにする

### 下部シート

- TODO/予定は基本「追加・編集シート」で完結
- シート内のスクロールと背景スクロールが競合しない
- 入力に集中できる配置、保存結果を即時提示
- 高さを超える内容でも主要ボタンと閉じる導線を失わない
- メモ編集UIは保留中。再開時に本文量に合わせてシート/全画面を選ぶ

### 共通状態

- Skeletonまたは短いローディング表現（通信段階で導入）
- 空状態: シンプルな説明 + 作成導線（装飾過多にしない）
- エラー: 具体的な原因と再試行導線（誤解を招く成功表示を避ける）
- Undo: 削除/完了など必要な操作に提示
- Focus: キーボード操作・VoiceOverで現在位置が分かる

## 6. TODO画面

### 基本画面

- 画面冒頭の「残りのタスク」サマリーカードを置かず、「すべて」と設定済みカテゴリのチップを配置。カテゴリは設定で追加・名前変更・並び替え・色変更・削除できる。各カテゴリの背景色・文字色はTODO行のカテゴリタグと共通にする。角丸四角形の2段ボタン（上段カテゴリ名11px・下段未完了件数10px）で表示し、件数は追加・完了・解除に追従。選択中は同系色のインナーリングで強調し、スプリング式の選択インジケーターを維持。「すべて」の選択中のみ従来のネイビー背景を使う。横スクロール可能。「これからすること」と右の件数見出しは廃止
- 未完了タスク: 行ベースのリスト表示（不必要に個別カード化しない）
- 行の左: 44pxタップ領域内のチェック操作
- 中央: タイトル（最大2行を基本、詳細では全文）と控えめなカテゴリ/期限
- 右: 必要に応じ作成者アバターや詳細表示導線
- 完了済み: 折りたたみエリア
- 画面下部の浮いたDock右端: ＋ 追加

### 作成/編集

- シートを開いた直後はキーボードを表示しない。TODOを追加した後はタイトル入力の右端に緑の丸チェックを短く重ねて表示し、シートを開いたまま入力値をクリアする。選択中カテゴリを保ってタイトル入力へフォーカスを戻す。編集で変更した内容は「変更を保存」またはシートを閉じたときに保存する。閉じる確認ダイアログは表示しない
- 入力必須はタイトルのみ
- カテゴリはTODO画面の色付き角丸タイルと同じ色・形で選ぶ。候補が多い場合は横スクロールし、選択中は同系色のインナーリングで示す
- 期限・詳細メモ・場所/URLは「詳細を入力」の中にまとめる。既存タスクにどれか詳細が入っていれば編集時は展開しておく
- 保存時はすぐ一覧へ反映（Phase 1ではローカルstate）
- 完了・元に戻す・削除・Undoを試せる

## 7. カレンダー画面

- 冒頭に画面タイトルを置かず、月間カレンダー（現在の年月・前後月切り替え）を先頭に表示
- カレンダーのヘッダーは曜日を短く表示。7列均等グリッド
- 今日/選択日は色と輪郭で区別
- 予定のある日付は控えめなドット（件数が多い場合の最大表示数を制限）
- メンバー1人の間は、ヘッダーに「自分」だけを表示し、TODO行の担当アバターと予定の担当選択を隠す。カレンダーは担当見出しのない42px時刻列＋1列のタイムラインにする。保存済みのA/B/ふたりの予定は値を変更せず同じ列に表示し、Bの所有者色・ラベルは出さない
- メンバーが2人になった後は**2人の1日を比較する縦型タイムライン**へ切り替える。ヘッダーと終日欄はA／Bの**2列だけ**。ヘッダーは各メンバーの表示名とプロフィール画像を出す。共有予定専用の3列目や「ふたりの予定」見出しを置かない。A・B・ふたりのいずれにも終日予定がない日は終日欄を表示しない。共有の終日予定はA+Bの2列をまたぐ横長チップとして個人用終日欄の下に置く
- 時刻付きの**ふたりの予定**は3列目を増やさず、A＋Bの2列をまたぐフル幅の紫色ボックスとして描画。個人予定はその上に表示でき、どちらも編集可能
- スケジュール全体を囲む白背景・外周ボーダー・外周シャドウは削除し、透過背景の上に控えめな横罫線と列境界だけを置く
- Aは青緑、Bはピーチ、ふたりはラベンダー。ダークモードも意味色を維持
- 同じ担当者の時刻付き予定が重複した場合、**重なりグループ内で最長の予定だけを時間どおりに表示**し、その他はその右側の「他N件」チップにまとめる。担当色の背景・文字・全周1px境界を使う小型ボタンとし、角丸は共通の`rounded-sm`、文字は12px、余白は縦2px／横4pxを基準にする。左辺だけを強調する境界や白い浮遊ピルにはしない。チップは時間軸の1時間目盛りに寄せ、タップすると正確な時刻・担当・カテゴリを含む予定一覧をシート表示し、各予定を編集できる
- 単独表示の短時間予定は実時間が5分でも最小36pxのカードを確保。タイトルを優先し、カードが狭い場合は時間の小文字だけ非表示（時間は目盛り・編集画面・ツールチップ・title属性で確認可能）。重なりグループの各予定は件数チップから開く一覧にタイトルと正確な時刻を表示
- 時間帯の範囲は選択日の予定に合わせて動的に計算（1時間=54px、ボックス最小高さ34px、前後余白）。時刻付き予定がない日は専用空状態
- 期限付きTODOはタイムライン下の独立したコンパクトな一覧に表示する（予定として重複保存しない）
- メンバーが2人のときだけ、編集シートで**各メンバー名の予定／ふたりの予定**を選択でき、メンバーのプロフィール画像も表示する。Firebaseを設定するとGoogleログイン・招待後に実メンバーが参加する。TODO/予定の共有同期ソースは実装済みだが、実環境での2人同期確認は未完了
- 固定デモデータはA/Bの予定を含むが、1人状態では所有者名を隠して一列に表示する。旧デモデータの追加処理は一度だけ行い、実データは上書きせず、削除済みサンプルを復活させない
- 予定追加はシートでタイトル・日時・担当/カテゴリ/場所/メモなどを編集
- 週表示・ドラッグによる時間割編集は初期版に含めない

## 8. メモ画面

- メモタブはグローバルメニューに残すが、画面には「メモ機能は開発中です」の案内だけを表示する
- メモの一覧・詳細・作成/編集UIと＋操作は、用途が決まるまで保留する
- メモ機能を再開するときに、具体的な利用シーンとTODO/予定との役割分担を先に整理する

## 9. アニメーション（2026-10-14 改良）

- **TODOの新規追加・完了・削除:** Motionの `AnimatePresence` と `layout` で行の出入り・高さ・後続アイテムの移動を連動させる。行の高さ変化は180ms、フェードは120msを目安にする
- **完了一覧:** 折りたたみを約160msで開閉。完了タスクの入退場も短くフェードさせる
- **残件数:** 数字が変化すると約160msで縦方向に切り替わる
- **メイン3タブ:** 選択背景がアイコンとラベル全体を囲み、`layoutId` で横へスライドする。アイコンとラベルのサイズは選択状態で変えず、ラベルの太さと色で選択中を示す
- **ページ切替:** `AnimatePresence(mode="wait")` で前の画面を消してから次を表示し、フェード時間は70–100msに抑える。設定画面は小さな水平移動を加える
- **カレンダー:** 月移動は約110msの水平スライド。選択日コンテンツは約100msで切り替える
- **メモ:** 現在は案内文だけのため、メモ固有の画面遷移や検索アニメーションはない
- **設定:** セクション内の入場アニメーションは使わない
- **操作:** Dock内の＋は控えめに縮小し、削除Undo通知は150msで出入りする
- **入力シート:** CSSドロワーは開くとき210ms、閉じるとき150ms。iPhoneキーボード表示時はアニメーションを停止し、`visualViewport` 位置調整を優先する
- **配慮:** `useReducedMotion` と `prefers-reduced-motion` を尊重し、端末設定で動きを減らしている場合は移動・スプリングを省略。操作の完了・データ保存はアニメーションの完了待ちにしない
- **禁止:** 全要素を常に揺らす演出、長いアニメーション、不要なページ全面スライド、紙吹雪

## 10. UIコンポーネント採用方針

| コンポーネント | 方針 |
| --- | --- |
| Button | `src/components/ui/button.tsx` の共通variantを使用。選択・モーションが必要な場面も共通variantを基礎にする |
| Input / Textarea / Label | `src/components/ui/` の共通部品を使用。入力文字16px以上、共通フォーカス表示 |
| Sheet / ConfirmDialog | Radix Dialogベースの共通部品。Sheetはsafe area/keyboard対応を維持する。TODO入力は有効な変更を閉じると保存し（新規作成は追加）、破棄確認は出さない。予定など確認が必要な場面はアプリ内Dialogに統一 |
| Switch | `src/components/ui/switch.tsx` を使用し、44px以上の操作領域と共通フォーカス表示 |
| Owner / Category | `owner-ui.tsx` / `category-ui.tsx` の表示・選択部品とテーマ色を共有 |
| Toast / Undo | 共通通知部品を使用。削除Undoは重なっても操作できる位置に積む |
| Tabs | 独自の固定Bottom Navigation |
| Checkbox | `src/components/ui/checkbox.tsx` を使用。チェック状態と44px以上の外側タップ領域を共通化 |
| Badge / Separator | 必要最小限 |
| Calendar（月グリッド） | 独自UI + date-fns。重い総合カレンダーライブラリを前提にしない |
| Icons | Lucideのみ原則 |
